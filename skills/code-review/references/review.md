# Shared review rules

- Read the full feature brief by ID before opening source files or evidence that contains code. Pass the same ID when delegating. Keep candidate findings and verdicts in their own messages.
- Review only the assigned scope. Follow related code as needed to establish behavior or evidence.
- Before reviewing code, apply all other relevant skills, including any omitted from the handoff. The assigned instruction files cover code-review.
- In every role, check applicable instructions, domain practice, and comparable code even when tests pass. Check that examples serve the same purpose and fit the language, framework, and supported versions. Respect priority and scoped exceptions. Avoid copying legacy patterns or known defects for consistency.
- Follow established conventions over personal preferences.
- Support findings with exact locations and evidence. For a defect, show the trigger and consequence. For a convention finding, cite the applicable rule or comparable code and explain the difference. A proven convention violation can stand without a runtime failure. For a general practice claim, show a concrete benefit or risk in the assigned code.
- Use prior validation as evidence about the checks it covered. Keep claims that the available evidence cannot settle open.
