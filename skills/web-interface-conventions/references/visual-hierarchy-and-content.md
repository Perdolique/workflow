# Visual hierarchy and content

Use this guidance when the task asks for a redesign or when approved sources leave a visual or content choice open. Do not change an approved hierarchy, copy, component choice, or asset only to match this reference. Raise a conflict when the design breaks confirmed behavior, accessibility, or technical constraints.

## Establish the page hierarchy

- Identify the page's main user goal, primary content or action, supporting groups, and optional material before styling.
- Treat the intended priority as a product decision. Ask when the task evidence and established patterns do not identify it.
- Put the primary task where users can find it early. Use clear heading levels, alignment, spacing, typography, and contrast to show the content order.
- Group content that belongs to one task or subject. Separate unrelated groups with consistent spacing, surfaces, borders, or backgrounds when those cues make the relationship clearer.
- Do not wrap every section in a card. Use a card for a self-contained subject or repeated item, and use headings and spacing for continuous content.

## Keep interface copy useful

- Add supporting copy only when it explains a purpose, context, constraint, consequence, next step, or recovery that the heading or control does not already express.
- Do not add a description below every heading or repeat the heading in a sentence.
- Put important words first. Keep paragraphs short, and use lists for separate points when that makes them easier to scan.
- When the task allows copy changes, remove or shorten filler while preserving technical meaning and text that users need to decide, act, or recover.

## Reveal secondary content deliberately

- Simplify and structure content before hiding it.
- Keep the primary action, information needed for a decision, current status, validation, active errors, and their recovery actions visible.
- Use native `details` and `summary` for short secondary content that only some users need near its context. Give the summary a clear label.
- Use tabs or an accordion only when users benefit from switching among related sections and product evidence supports hiding them.
- Use a dialog for a separate temporary task that needs focused interaction, not as storage for supporting page content.

## Add purposeful visual distinction

- Make the structure clear before adding decoration.
- Use existing semantic tokens for restrained surface, border, or color accents that reinforce content roles. Keep strong emphasis for the few items that need attention.
- Use familiar project icons as supporting cues. Pair an icon with text when its meaning is not clear from an approved pattern or nearby label. Do not use icons to repair unclear structure.
- Use an approved illustration or graphic only when it explains a concept or provides a requested visual anchor.
