# Development guide

Development is tracked in [GitHub Issues](https://github.com/example-maintainer/pantry-api/issues) and the repository Project. Issues hold the agreed work scope. Accepted architecture decisions belong in `docs/decisions/`.

## Plan tasks when an epic starts

Review the epic, current code, issues, and accepted decisions. Resolve required choices with the owner, then create small, useful, verifiable sub-issues. E1 starts with Ready task #217, which depends on accepted decision #216. E1 stays open until its deployed foundation meets acceptance.

The owner chooses all libraries and tools. Explain alternatives and the full added package set before requesting a choice. Existing experience does not establish approval.

## Project workflow

The status sequence is Backlog → Ready → In progress → Done. Close issues only after acceptance is verified. Future ideas have no v1 milestone until selected.
